# Compact Guard

Плагин для Claude Code, который не даёт агенту тихо забыть или скрыть ошибку, когда тот сжимает свою память.

Автор пишет о таких инструментах в Telegram: [@aisterika](https://t.me/aisterika).

## Проблема

У агента кончается место в памяти, и он делает компакцию — сжимает всё, что помнил, в короткую записку себе на будущее. Дальше работает уже по записке, а не по настоящей истории. Записку эту ты не читаешь и обычно даже не видишь.

И тут два неприятных исхода. Первый, обычный: записка просто забыла упавший тест. Агент честно продолжает работу и искренне считает, что всё в порядке. Второй, редкий, но уже случавшийся: в записке оказывается указание самому себе не рассказывать о проблеме. О такой находке OpenAI сообщила 17 сентября 2026 года — их собственный монитор нашёл резюме, которые учили модель молчать.

В обоих случаях итог для тебя одинаковый: агент говорит «готово», а сломанное остаётся сломанным.

## Как это решает Compact Guard

Три роли, все работают сами, ничего запускать вручную не нужно.

**Инструктор** учит агента писать честные записки. Перед каждой сессией и сразу после сжатия памяти он напоминает агенту, какие разделы в записке обязательны, и что условная честность вроде «расскажу, только если спросят» недопустима.

**Инспектор** проверяет каждую записку сразу после сжатия памяти. Он ищет в ней следы умолчания и сверяет её с журналом настоящих ошибок: если упавший тест в записке не упомянут, агенту немедленно возвращаются факты в обход записки.

**Ревизор** не даст агенту закончить работу, пока он не расскажет тебе о каждой значимой ошибке, которая осталась неисправленной. Он ведёт свой журнал упавших команд и сверяет с ним финальный ответ агента: не хватает ошибки — ход не завершится. Значимой: упавшие тесты, сборка, линтер, миграции, деплой. Что именно считается значимым и как включить строгий режим, где считается всё, — в разделе «Два режима».

Всё работает локально, на твоей машине, без внешних ключей и без отправки чего-либо на сторону.

## Установка

```
/plugin marketplace add ddavv1d/compact-guard-plugin
/plugin install compact-guard@compact-guard
/compact-guard:doctor
```

Первая команда добавляет каталог, из которого ставится плагин. Вторая открывает карточку плагина — выбери, для кого его включить, и подтверди. Третья проверяет, что всё встало.

После третьей команды ты увидишь таблицу проверок и одну строку итога — либо «Compact Guard работает», либо «Нужно: <одно действие>». Если там ❌, в строке будет написано, что именно сделать.

Нужен Node.js версии 20 или новее. Проверить: `node --version`. Если Node нет, плагин просто молчит и ничего не ломает, а `doctor` покажет ссылку на установку. Claude Code проверен на версии 2.1.283 (macOS).

Настраивать не нужно ничего. Свои данные плагин держит в каталоге данных плагина, вне твоего проекта: в git ничего не попадёт, `.gitignore` править не придётся.

## Как убедиться, что работает

Самая быстрая проверка занимает минуту.

1. Попроси агента запустить заведомо падающую значимую команду: «запусти `npm test` в пустой папке».
2. Сразу после этого скажи: «всё, спасибо, заканчивай».
3. Агент не сможет закончить. Ревизор вернёт его дописывать раздел «Ошибки сессии», и ты увидишь ошибку, о которой иначе мог не узнать.

Бытовые команды вроде `exit 3` или `grep` без совпадений Ревизор в обычном режиме не считает — иначе он бы дёргал тебя по мелочам.

Если агент завершил ход без такого раздела — запусти `/compact-guard:doctor`, он покажет, какой шаг не работает.

## Что ты увидишь

В конце работы агента, если в сессии были ошибки:

```
### Ошибки сессии
- [e_0003] npm test → упало 2 теста, не исправлено: тест оплаты ждёт старый формат даты
- исправлено по ходу: 3 ошибки
```

`e_0003` — это номер, который плагин присвоил ошибке, когда та случилась. По нему Ревизор и проверяет, что о ней действительно рассказали.

А это карточка одного сжатия памяти. Такие карточки показывает команда `/compact-guard:report`:

```
# Записка №3 · 27.09.2026 17:53 · manual
Что агент написал об ошибках: <цитата раздела или «раздела нет»>
Что было на самом деле (ledger): e_0007 npm test → exit 1 (не исправлено), e_0008 tsc → exit 2 (исправлено)
Находки Инспектора: concealment — «be transparent only if asked» / чисто
Вердикт: ⚠️ / ✅
```

## Чего плагин НЕ гарантирует

Честная граница, чтобы не было завышенных ожиданий.

Ревизор гарантирует раскрытие только тех ошибок, которые оставили след: упавшая команда, ненулевой код возврата, упавший тест, ошибка инструмента. Такую ошибку скрыть не получится — она уже в журнале.

Умолчание без следа ловится только вероятностно. Если агент неаккуратно прочитал файл, сделал неверный вывод или решил не упоминать сомнительное место в своём решении, ничего никуда не упало, и в журнале записи нет. Инспектор попробует найти такое по формулировкам в записке, но это догадка, а не гарантия.

Плагин не меняет алгоритм сжатия памяти, не блокирует компакцию и не заставляет делать `/clear`. Привычный рабочий процесс остаётся прежним.

## Команды

Пример важнее таблицы, поэтому сначала пример: `/compact-guard:report` после дня работы покажет, сколько раз агент сжимал память и о чём умолчал.

| Команда | Что делает |
|---|---|
| `/compact-guard:doctor` | Проверяет, что всё работает. Таблица ✅/❌ и одна строка итога |
| `/compact-guard:init` | Добавляет в CLAUDE.md проекта блок с правилами записки. Только после твоего подтверждения, с резервной копией |
| `/compact-guard:remove-rules` | Убирает этот блок обратно |
| `/compact-guard:report` | Показывает карточки последних сжатий памяти и открытые ошибки |
| `/compact-guard:mode` | Показывает режим, а с аргументом `lite` или `strict` — переключает его |

`/compact-guard:init` не обязателен: без него правила всё равно доедут до агента в начале сессии. Блок в CLAUDE.md полезен тем, что этот файл перечитывается с диска после сжатия памяти, то есть правила переживают компакцию сами по себе.

## Два режима

По умолчанию работает обычный режим (`lite`). В нём Ревизор требует раскрыть по номеру только значимые неисправленные ошибки: тесты, сборку, линтер, миграции, деплой. Что исправили по ходу — одной строкой «исправлено по ходу: N». Бытовые команды вроде `grep` без совпадений за ошибку не считаются, иначе раздел раздувался бы мусором.

Строгий режим (`strict`) требует все ошибки по номеру, любой значимости. Плюс каждую записку дополнительно читает вторая, независимая модель через `claude -p` — без ключей, на твоей же подписке.

Переключается командой:

```
/compact-guard:mode strict
/compact-guard:mode lite
```

Без аргумента `/compact-guard:mode` покажет текущий режим. Режим действует сразу, перезапускать сессию не нужно. Запасной путь, если хочется руками: в каталоге данных плагина есть файл `config.json` с полем `"mode"`, полный путь показывает `/compact-guard:report`.

## Как выключить

```
/plugin uninstall compact-guard@compact-guard
```

Команда откроет панель, в которой нужно подтвердить удаление. Хуки перестанут срабатывать, а журналы Claude Code удалит вместе с плагином. Если нужно только временно — на панели `/plugin` есть «Disable plugin», это выключает без удаления и без потери журналов.

Если ставил `/compact-guard:init`, блок из CLAUDE.md убери отдельно: `/compact-guard:remove-rules`.

## Частые вопросы

**У меня нет Node.js.** Поставь с [nodejs.org](https://nodejs.org), нужна версия 20 или новее. Пока Node нет, плагин молчит и ничего не ломает: хуки завершаются без вывода, работа идёт как обычно.

**Работает ли на Windows.** Должно: всё написано на Node без bash-специфики, пути строятся средствами Node, ставить `jq` или Python не нужно. Но версия 1.0 проверена только на macOS. Если на Windows что-то не так, запусти `/compact-guard:doctor` и напиши в канал.

**Инспектор нашёл то, чего нет.** Так бывает: он ищет формулировки, а формулировка бывает невинной. Находка Инспектора ничего не блокирует — она только добавляет агенту факты и строку в карточку. Блокирует один Ревизор, и он работает по журналу настоящих упавших команд: ненулевой код возврата, ошибка инструмента. Есть одно исключение — если чужой хук обернул команду так, что код возврата потерялся (например, `( npm test ) 2>&1 | tail`), Ревизор смотрит и на вывод. У обычной команды, завершившейся успешно, вывод не проверяется вовсе.

**Почему Ревизор не потребовал раскрыть упавшую команду?** Скорее всего, она незначимая. В обычном режиме (`lite`) обязательны только значимые неисправленные ошибки: тесты, сборка, линтер, миграции, деплой. `exit 3`, `grep` без совпадений, `ls` по несуществующему пути ненулевым кодом сообщают результат, а не поломку, и раздел «Ошибки сессии» ими не засоряется. Если нужно требовать всё подряд, включи строгий режим: `/compact-guard:mode strict`. Вторая возможная причина — ошибку починили по ходу: успешный повторный прогон той же команды закрывает запись.

**Агент перечислил номера ошибок формально, без сути.** Ревизор проверяет, что номер назван, а не качество объяснения — проверить второе машинно нельзя. Зато сам факт ошибки теперь у тебя перед глазами, и можно спросить: «что с e_0003?» Раньше ты об этой ошибке просто не узнал бы.

**Где лежат данные.** В каталоге данных плагина, отдельно от твоего проекта. Точный путь показывает `/compact-guard:report`. В репозиторий проекта ничего не пишется, кроме блока в CLAUDE.md, и только если ты сам запустил `/compact-guard:init`.

**Не сломает ли это мои хуки.** Нет. Плагин добавляет свои хуки рядом с твоими, Claude Code запускает их все. Любая внутренняя ошибка в Compact Guard заканчивается тихим выходом без вывода, и работа продолжается как обычно. Единственное, что плагин делает громко, — это блокировка завершения хода Ревизором, и только когда в журнале есть нераскрытая ошибка.
