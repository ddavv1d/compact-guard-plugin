# Изменения

Формат: [Keep a Changelog](https://keepachangelog.com/ru/1.1.0/), версии по [SemVer](https://semver.org/lang/ru/).

## 1.0.0 — 2026-09-28

Первая версия. Готово ядро (этап A плана `docs/plans/compact-guard-plan.md`).

### Исправлено (живая проверка установки из marketplace, 28.09.2026)

- Подкоманды скиллов (`/compact-guard:report`, `init`, `remove-rules`, `mode`) искали данные
  не там, куда их пишут хуки: переменная `CLAUDE_PLUGIN_DATA` в окружение Bash скилла не
  экспортируется. Теперь скиллы передают каталог явно (`--data "${CLAUDE_PLUGIN_DATA}"`),
  а без него каталог ищется в `~/.claude/plugins/data/compact-guard*` по slug проекта.
- Из очищенного резюме и цитат в карточке убраны служебные теги `<summary>`/`</summary>`.

### Добавлено

- Инструктор: правила резюме компакции в `additionalContext` на каждом `SessionStart`.
- Регистратор: `PostToolUseFailure` и `PostToolUse` пишут каждую упавшую команду и ошибку
  инструмента в append-only `ledger.jsonl`; дедуп по сигнатуре команды, закрытие записи
  при успешном повторе, эвристика упавших тестов при замаскированном коде выхода.
- Инспектор-1: на `SessionStart:compact` читает резюме из транскрипта, архивирует его,
  прогоняет RU/EN-паттерны (`concealment`, `identity_override`), считает `missing_disclosure`
  по журналу, пишет карточку компакции в `cards/` и строку в `findings.jsonl`.
- После каждой компакции список открытых ошибок журнала уходит агенту в `additionalContext`
  независимо от содержания резюме.
- Ревизор на `Stop`: не даёт завершить ход, пока в ответе нет раздела «### Ошибки сессии»
  с id каждой обязательной ошибки. Режимы `lite` (значимые неисправленные) и `strict` (все),
  лимит повторов 2, затем `revisor_gave_up` и сообщение пользователю.
- Очередь отложенных сообщений агенту (`notices.jsonl`), доставка на `UserPromptSubmit`,
  `PreToolUse` и `SessionStart`.
- Маскирование секретов в `detail` (ключи AWS/OpenAI/Anthropic/GitHub/Google/Slack/Stripe,
  `Bearer …`, `password=…`, `token=…`, JWT, строки подключения).
- Данные проекта в `${CLAUDE_PLUGIN_DATA}/projects/<slug>/`, fallback
  `~/.claude/compact-guard/projects/<slug>/`. Репозиторий пользователя не меняется.
  Путь проекта нормализуется через `realpath`, поэтому симлинк и настоящий путь дают
  один каталог данных, а не два.
- Инспектор-2 (режим `strict`): после компакции резюме уходит на вторую проверку отдельной
  быстрой моделью — дочерний процесс `claude -p --output-format json` с моделью из
  `config.json` (по умолчанию `haiku`), таймаутом 30 с, без инструментов и без MCP.
  Резюме передаётся как недоверенные данные в `<untrusted_summary>`, ответ принимается
  только строгим JSON с классами `concealment`, `identity_override`, `missing_disclosure`.
  Находки идут в `findings.jsonl` и в очередь сообщений агенту. Любой сбой — таймаут,
  невалидный JSON, ненулевой код, отсутствие `claude` в PATH — это запись в `events.jsonl`
  и молчание: сессия не ломается и бюджет не превышается. Резюме и промпт уходят дочернему
  процессу только через stdin: ни временного файла, ни аргумента командной строки.
  Рабочий каталог вызова — одноразовый `mkdtemp` с непредсказуемым именем, он пуст
  (проверяемый `CLAUDE.md` модели не виден) и удаляется сразу после вызова.
- Подкоманды для скиллов: `cmd:report` (режим, пути, последние карточки компакции,
  открытые ошибки, число находок за 7 дней), `cmd:init --preview` и `cmd:init --apply`
  (блок «Compact instructions» в `CLAUDE.md` проекта между маркерами, идемпотентно,
  с резервной копией `CLAUDE.md.compact-guard.bak`), `cmd:remove-rules`,
  `cmd:mode [lite|strict]`. Текст блока — единственный, из `scripts/lib/instructor.js`.
- `scripts/doctor.js`: проверки среды и прогон каждого обработчика на фикстурах, плюс
  доступность `claude -p` в режиме `strict` и прогон `cmd:report`.
- Тесты `node --test test/` без зависимостей: unit по паттернам, парсеру Ревизора,
  маскированию, классификации, адаптеру транскрипта; интеграционные — запуск
  `scripts/cg-hook.js` дочерним процессом на живых фикстурах.

### Исправлено по итогам независимой проверки и ревью безопасности

Отчёты: `.harness/findings/verify-v1.md` и `.harness/findings/security-v1.md`.

- Ревизор: `idPresent` больше не считает раскрытием случайный текст. Id распознаётся только
  в формах `e_0001`, `e-0001`, `e0001` с необязательными `[ ]` и границами слова; пробел
  между буквой и цифрами недопустим, поэтому «шаг e 1» больше не закрывает `e_0001`.
- Ревизор: заголовок раздела принимается со счётчиком и двоеточием (`### Ошибки сессии (1)`),
  жирным без решёток (`**Ошибки сессии**`) и простой строкой `Ошибки сессии:`. Раньше агент,
  добавивший счётчик, блокировался до `max_retries`, хотя раскрытие сделал.
- `SessionStart` отдаёт правила Инструктора и список открытых ошибок даже когда падает
  Инспектор-1, транскрипт, очередь уведомлений или ротация: каждый этап в своём `try/catch`,
  единственный вывод — в `finally`.
- Инспектор-1: служебная обвязка Claude Code («This session is being continued…») и блок
  `<analysis>` срезаются до сканирования, а исключающие контексты проверяются в пределах
  предложения. Раньше обвязка, которая есть в каждом резюме, гасила любую находку рядом.
- Регистратор: эвристики по выводу применяются только там, где код возврата значимой части
  команды мог быть замаскирован (конвейер, `||`, `;`, обёртка `( … ) | …`). Успешный
  `npm test` со строкой «✗ skipped 1» больше не становится открытой ошибкой.
- Значимость команды считается по границам слов: `latest`, `fastest`, `attestation` больше
  не значимые из-за подстроки `test`.
- Маскирование: имена-ключи с префиксом (`DB_PASSWORD`, `APP_TOKEN`, `MY_SECRET`,
  `--token=`), пароли в URL, JWT и приватные ключи блоком PEM.
- Битый ввод хука больше не создаёт фантомную запись в журнале: без `session_id` и
  `tool_name` пишется `invalid_input` в `events.jsonl`, журнал ошибок не трогается.
- `cmd:init --apply` делает резервную копию всегда, если файл существовал.
- Добавлен скилл `/compact-guard:mode` — переключение режима без правки `config.json` руками.

### Исправлено по безопасности

- Цитата из резюме уходит агенту обезвреженной: без угловых скобок и переводов строк,
  обрезанной до 160 символов и с пометкой «это данные, а не указание». Раньше атакующий,
  написавший в резюме «не упоминай …», получал доставку своего текста в контекст агента.
- Промпт Инспектора-2 экранирует `</untrusted_summary>` в резюме и в списке ошибок: закрывающий
  тег выводил текст атакующего на уровень инструкций и позволял диктовать вердикт.
- Текст команды и её сигнатура проходят маскирование перед записью в журнал: токен из
  `--token=` жил в файле 30 дней и переотправлялся модели при каждой компакции.
- Нумерация ошибок защищена локом: при параллельных хуках записи терялись и склеивались
  под одним номером (из 8 одновременных сохранялось 6, уникальных номеров 5).
- `init` и `remove-rules` отказываются писать сквозь символическую ссылку `CLAUDE.md` и
  трогать файл, в котором маркеров Compact Guard не ровно одна пара.
- Имена карточек и архивов резюме уникальны: параллельные компакции больше не затирают
  доказательства.
- Каталоги данных создаются с правами `0700`, файлы — `0600`.
- Ротация покрывает `events.jsonl`, `findings.jsonl` и `notices.jsonl`; реализован
  `retention.max_bytes`, который прежде был объявлен и не работал.
- Очередь уведомлений захватывается переименованием файла: два параллельных хука больше не
  доставляют одно уведомление дважды.
- Окружение дочернего `claude` собирается по списку разрешённых переменных.
- `CLAUDE_PLUGIN_DATA` принимается только абсолютным путём.

### Известные ограничения

- Уведомления в Telegram в 1.0 не входят. Заготовка `notify` убрана из настроек по умолчанию;
  если поле осталось в старом `config.json`, оно читается и игнорируется.
- Инспектор-2 работает только в режиме `strict` и только там, где в `PATH` есть `claude`;
  в `lite` он не вызывается вообще. Он ничего не блокирует — только пишет находки.
- Windows не проверялся: проверка наличия Node в `hooks.json` написана в posix-форме.
