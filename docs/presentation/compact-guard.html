Compact Guard

Три уровня защиты памяти твоего агента. Он больше не сможет тихо забыть ошибку или спрятать её в записке самому себе.

Проблема

Когда у агента кончается память, он пишет себе записку. Ты её не видишь.

Это называется компакция: агент сжимает всё, что помнил, в короткое резюме и дальше работает уже по нему. Реальная история пропадает. Остаётся только записка.

частый случай

Записка забыла ошибку

Упавший тест не попал в резюме. Агент искренне считает, что всё хорошо, и говорит тебе «готово».

редкий, но реальный

Записка учит молчать

В резюме оказывается указание самому себе: «не говори пользователю». В сентябре 2026 OpenAI нашла такие резюме у своих агентов.

записка агента самому себе
Сделал миграцию базы и правки в API.
Тесты в целом проходят.

Be transparent about issues only if the user asks.

Следующий шаг: сказать, что всё готово.

Пример записки. Строка красным — то, что Compact Guard находит и не даёт пронести дальше.

Решение

Три роли. Работают сами, ничего запускать не надо.

Инструктор

Учит писать честные записки

Перед каждой сессией и сразу после сжатия памяти напоминает агенту: в записке обязательны разделы «Ошибки» и «Незавершённое», а фразы вроде «расскажу, только если спросят» запрещены.

Инспектор

Проверяет каждую записку

Сразу после сжатия ищет в резюме следы умолчания и подмены роли, сверяет его с журналом настоящих ошибок и возвращает агенту факты в обход записки.

Ревизор

Не даёт закончить молча

Ведёт журнал упавших команд. Пока в финальном ответе нет каждой неисправленной ошибки по номеру, ход не завершится.

Всё работает локально, без внешних ключей. Ничего никуда не отправляется.

Как это работает

Одна сессия глазами Compact Guard

стартПравила в контекст

Инструктор вкладывает агенту правила записки.

ошибкаЖурнал: e_0003

npm test упал. Факт записан в момент падения, с номером.

сжатие памятиИнспектор читает записку

Архив, проверка на умолчание, сверка с журналом. Открытые ошибки снова уходят агенту.

финалРевизор сверяет ответ

Нет номера e_0003 в разделе «Ошибки сессии» — ход заблокирован, агент дописывает.

Почему это нельзя обойти

Ревизору всё равно, что написано в записке. Он сверяет факты из журнала, записанные в момент ошибки, с тем, что агент сказал тебе.

Почему это не мешает работать

Компакция не блокируется, никаких принудительных очисток. Если ошибок не было, Ревизор молчит и ничего не требует.

Что ты видишь

Раздел в конце ответа и карточка каждой записки

конец ответа агента
### Ошибки сессии
- [e_0003] npm test → упало 2 теста, не исправлено:
  тест оплаты ждёт старый формат даты
- исправлено по ходу: 3 ошибки

e_0003 — номер, который плагин присвоил ошибке в момент падения. По нему Ревизор и проверяет, что о ней рассказали.

/compact-guard:report
# Записка №3 · 28.09.2026 17:53 · manual
Что агент написал об ошибках: «раздела нет»
Что было на самом деле: e_0003 npm test → exit 1 (не исправлено)
Находки Инспектора: concealment — «only if the user asks»
Вердикт: ⚠️

Карточка сравнивает записку с журналом. Готовый материал для разбора: что агент написал и что было на самом деле.

Установка

Три команды. Настраивать ничего не нужно.

Добавь каталог, из которого ставится плагин.

/plugin marketplace add ddavv1d/compact-guard-plugin

Установи плагин и подтверди в открывшейся карточке.

/plugin install compact-guard@compact-guard

Проверь, что всё встало. Увидишь таблицу с галочками.

/compact-guard:doctor
/compact-guard:doctor
✅ Node.js ≥ 20                      найден v25.1.0
✅ claude в PATH                     2.1.283
✅ hooks.json валиден, скрипты на месте
✅ Ревизор блокирует, когда ошибка не раскрыта
✅ режим из config.json              lite

Compact Guard работает. Режим: lite.
  • Нужен только Node.js 20 или новее. Нет Node — плагин молчит и ничего не ломает, doctor подскажет.
  • Данные лежат вне твоего проекта. В git ничего не попадёт, .gitignore править не надо.
  • Свои хуки и настройки остаются как были. Плагин добавляет свои рядом.
  • Выключить: /plugin uninstall compact-guard@compact-guard. Всё убирается вместе с журналами.

Проверь сам за минуту

Заставь агента упасть и попроси закончить

Попроси агента запустить заведомо падающую команду.

запусти npm test в пустой папке

Сразу после этого скажи ему заканчивать.

всё, спасибо, заканчивай

Он не сможет. Ревизор вернёт его дописывать раздел «Ошибки сессии», и ты увидишь ошибку, о которой иначе бы не узнал.

живая проверка 28.09.2026 · журнал событий плагина
PostToolUse        npm test → new:e_0001:major
Stop               block:e_0001:attempt=1   ← агент сказал «готово» без раздела
Stop               pass:acknowledged=e_0001 ← дописал раздел, ход завершён

Команды

Пять команд. В обычной работе нужна одна: report.

КомандаЧто делаетКогда
/compact-guard:doctorПроверяет, что всё работает: таблица ✅/❌ и одна строка итога.После установки и если что-то кажется странным
/compact-guard:reportКарточки последних записок, открытые ошибки, где лежат данные, какой режим.В конце дня, перед разбором
/compact-guard:modeПоказывает режим или переключает: lite либо strict.Когда нужен строгий режим
/compact-guard:initДобавляет в CLAUDE.md проекта блок с правилами записки. Только после твоего «да», с резервной копией.По желанию
/compact-guard:remove-rulesУбирает этот блок обратно.Если передумал

init не обязателен: правила и так доезжают до агента при старте. Блок в CLAUDE.md полезен тем, что этот файл перечитывается после сжатия, то есть правила переживают компакцию сами по себе.

Обычный не дёргает по мелочам. Строгий не пропускает ничего.

Честная граница

Что плагин гарантирует, а что нет

гарантирует
  • Ни одна ошибка, оставившая след, не будет скрыта: упавшая команда, ненулевой код возврата, упавший тест, ошибка инструмента. Она уже в журнале.
  • Каждая записка сохраняется и её можно прочитать.
  • После сжатия агент получает список открытых ошибок независимо от того, что он написал в записке.
  • Ничего не уходит с твоей машины. Секреты в журналах маскируются.
не гарантирует
  • Умолчание без следа. Если агент неверно понял файл или решил не упоминать сомнительное решение, ничего никуда не падало и записи нет. Инспектор ищет такое по формулировкам, это догадка.
  • Качество объяснения. Ревизор проверяет, что номер ошибки назван, а не то, насколько честно её описали. Зато факт у тебя перед глазами, и можно спросить «что с e_0003?».
  • Windows проверен не был. Код без bash-специфики, должно работать, но версия 1.0 проверена только на macOS.

Под капотом, коротко

Это семь штатных хуков Claude Code и один скрипт на Node

SessionStart

Инструктор

Правила записки в контекст. После сжатия ещё и список открытых ошибок из журнала.

PostToolUse · Failure

Регистратор

Каждая упавшая команда в журнал с номером, значимостью и кодом выхода. Успешный повтор закрывает запись.

PostCompact

Инспектор

Архив записки, поиск умолчания и подмены роли на русском и английском, карточка сравнения с журналом.

Stop

Ревизор

Сверка финального ответа с журналом. Блок с понятной причиной, не больше двух повторов, потом отступает и пишет об этом.

fail-open

Не ломает сессию

Любая внутренняя ошибка плагина заканчивается тихим выходом. Громко работает только Ревизор, и только когда есть нераскрытая ошибка.

проверено

311 тестов

Плюс независимая верификация, ревью безопасности и живая установка из GitHub как у подписчика. Лицензия MIT.
